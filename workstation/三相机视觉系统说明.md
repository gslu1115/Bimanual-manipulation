# 三相机视觉系统

正式观测名称固定为 `scene_camera`、`left_wrist_camera`、`right_wrist_camera`。相机只提供观测和记录；当前抓放仍由仿真真值、Lula IK、物理关节驱动和夹指接触执行。完整实测结果见 [VALIDATION.md](VALIDATION.md)。

## 真实 Stage 层级

从本机 Isaac Sim 6.1 官方 Franka USD 的实际 Stage 中确认了两个带 `RigidBodyAPI` 的物理手掌。相机挂在这些刚体 link 下，不能挂在同名外观网格下。

```text
/World
├── perception_rig
│   └── scene_camera
├── Robots
│   ├── panda_left
│   │   └── panda_hand
│   │       └── left_wrist_camera_mount
│   │           └── left_wrist_camera
│   └── panda_right
│       └── panda_hand
│           └── right_wrist_camera_mount
│               └── right_wrist_camera
└── Cameras
    ├── overhead                 保留的 debug camera
    └── oblique                  保留的 debug camera
```

腕部 mount 是无碰撞、无刚体 API 的 Xform，相机自身局部变换为 identity。**机器人 prim hierarchy 自动随动：YES；Python 每帧 set_world_pose：NO。** Python 只在读取观测时获取渲染器当前外参。更换机器人资产时，代码重新遍历并确认唯一物理 `panda_hand`；找不到、找到多个或遇到不可编辑的 instance proxy 均直接报错。

## 配置与性能开关

沿用原来的 `cameras` 列表，旧 `position/look_at/up` 固定相机配置仍兼容。新增全局设置：

```json
"camera_system": {
  "enabled": true,
  "save_images": true,
  "recording_enabled": false,
  "render_interval_steps": 4,
  "capture_interval_steps": 12,
  "warmup_render_frames": 12
}
```

- 每个相机有 `enabled`、`role`、`type`、分辨率、焦距、aperture、clipping 和 annotation。腕部安装外参只在 mount 上配置。
- 默认每 4 个物理步渲染一次；`recording_enabled=false` 时只在原有任务阶段显式保存，不进行持续大量采集。
- `recording_enabled=true` 时，每 `capture_interval_steps` 个物理步保存一组 `recorded/frame_XXXXXXXX_*`；该间隔必须是渲染间隔的整数倍。
- `save_images=false` 时，内存中仍可获取 RGB、深度、实例标签，不写 PNG/NPY/实例标签文件，只保存小型标定和传感器报告。
- P1 低频模式可设渲染间隔 `12`、采集间隔 `24`、持续记录关闭，并使用 `-NoSaveImages`。物理仍为原有 120 Hz，PhysX 参数不变。
- 全局 `enabled=false` 或 `-NoSensors` 保留相机 prim，但不创建 render product；`observe_cameras()` 返回空 `cameras`。
- 原来的 `overhead/oblique` 保留原 prim 和参数，默认关闭采样。旧双臂视频模式会按其依赖启用这两个 debug render product，因此可能同时产生五个 product；正式 observation 仍只包含三台正式相机。

```powershell
# 本机安装目录为 D:\Issaccc；启动器也能在默认 D:\isaacsim 不存在时回退到这里。
# 九盒相机 smoke test：HOME、左右各一次独立运动、低频无图像保存检查。
powershell -ExecutionPolicy Bypass -File .\workstation\launch.ps1 -IsaacRoot D:\Issaccc -CameraCheck -Headless

# 三相机检查 + 原固定单盒完整物理回归 + 各抓放阶段图像。
powershell -ExecutionPolicy Bypass -File .\workstation\launch.ps1 -IsaacRoot D:\Issaccc -CameraCheck -SinglePickPlace -Headless

# 正常单盒运行，不保存大型相机文件。
powershell -ExecutionPolicy Bypass -File .\workstation\launch.ps1 -IsaacRoot D:\Issaccc -SinglePickPlace -Headless -NoSaveImages

# 持续采集，注意磁盘容量及 I/O 开销。
powershell -ExecutionPolicy Bypass -File .\workstation\launch.ps1 -IsaacRoot D:\Issaccc -SinglePickPlace -Headless -CameraRecording
```

## 与真机迁移路线的边界

本次实现的是仿真相机层，不是路线文档中的完整 `ObservationPacket / SimSensorAdapter / PrivilegedRecord`，也没有接入视觉闭环。下面的 `observe_cameras()` 是采集与调试接口，包含渲染器实例分割及原始 `camera_params`；实例 ID、语义映射和仿真验证真值只能作为独立标签/诊断数据。后续传感器适配器必须筛选 RGB-D、K、可标定外参和同步机器人状态，不能把此调试字典整体交给可迁移策略。

原单臂/双臂控制器仍是仿真真值开发基线；当前主线继续遵循 [感知决策执行闭环与真机迁移路线](../感知决策执行闭环与真机迁移路线.md)，先打通可观测接口与视觉估计。本次不改变该开发顺序，也不实现批量评估、训练或新技能。

## 统一 observation 与标定

```python
observations = env.observe_cameras(refresh=True)
frame = observations["cameras"]["left_wrist_camera"]
# rgb: H×W×3；depth: H×W，米；instance_segmentation: H×W
# intrinsics: 3×3 K
# extrinsics: 当前世界位置、wxyz、USD/OpenCV 齐次变换及帧时间
# instance_info: 仿真实例 ID 与语义映射；camera_params: 原始渲染参数
```

不传 `refresh=True` 时读取最近已渲染帧，不暗中推进物理；使用返回的 `physics_frame_index/simulation_time_s` 判断其时刻。显式 capture 默认进行 12 次渲染刷新，物理保持不动，用于等待 Replicator 数据就绪。`render_frame_index` 是本程序的渲染调用计数，不是 Hydra 内部全局帧编号。

每个 `<prefix>_<camera>_calibration.json` 记录对应渲染帧的 K、分辨率、世界平移/旋转、外参、父节点、物理帧编号、仿真时间。单独的 `<camera>_calibration.json` 是启动时 authored USD 初始参数，明确标为 `authored_initial_usd_not_a_rendered_frame`，**不能作为运动腕相机的逐帧标定**。

| 坐标 | 约定 |
|---|---|
| 世界 / Panda hand | 米制；世界 Z-up；hand 为实际物理 link 局部坐标 |
| USD 相机 | `+X` 右、`+Y` 上、`-Z` 向前 |
| OpenCV optical | `+X` 右、`+Y` 下、`+Z` 向前 |
| 四元数 | 一律 `wxyz` |
| 输出矩阵 | 列向量；`T_world_from_camera_*` 将相机坐标变换到世界 |
| 原始 cameraViewTransform | Replicator 世界到 USD 相机的行向量矩阵；取逆再转置 |
| 深度 | `distance_to_image_plane` 光轴深度，米；背景可为 `inf` |

`T_world_from_camera_opencv = T_world_from_camera_usd @ diag(1,-1,-1,1)`。只对有限正深度使用 `p_camera = depth * inv(K) @ [u,v,1]`。当前无畸变针孔模型，不模拟真实 RGB-D 噪声或 D405 硬件误差。

内参为最终 scene `fx=fy=640, cx=320, cy=240`；两腕 `fx=fy=355.5556, cx=320, cy=240`。实际腕部世界外参随姿态改变，应查看对应帧文件。

实际 HOME 示例取自 `outputs/camera_reference_preview_02/candidate_HOME_*_calibration.json`，物理帧 `312`、仿真时间 `2.6 s`。以下是渲染帧世界位姿，不是 mount 局部安装参数：

| 相机 | world translation，m | world rotation，wxyz（USD） |
|---|---|---|
| scene | `[0,-0.41,1.76]` | `[0.9885545,0.1508642,0,0]` |
| left wrist | `[-0.3599993,-0.0553771,1.3208095]` | `[0.0000011703,0.0000005008,-0.2832986,-0.9590317]` |
| right wrist | `[0.3600010,-0.1853769,1.3205611]` | `[0.0000012542,-0.0000002179,0.2851312,-0.9584885]` |

## 验证与输出

所有运行使用独立的 `workstation/outputs/` 子目录，完整生成物由 Git 忽略。最终配置的精选图像、逐帧标定及物理报告已归档到 [docs/three_camera](docs/three_camera/README.md)，可从仓库下载；下文 `outputs/` 路径指本机完整记录。

- `camera_rig.json`：实际 hand、mount、camera 路径、参数和最近帧信息。
- `camera_validation.json`：逐帧数据尺寸/有限深度、渲染外参与物理 hand×mount 比较、左右独立随动、固定相机漂移、低频无图像保存、可选完整抓放结果。
- `camera_performance.json`：渲染、数据读取、保存耗时及 `nvidia-smi` 显存采样。显存是整块 GPU 已用量，包含桌面等其他占用，不是进程独占显存。
- `check_HOME_INITIAL_*`、`check_panda_left_MOVED_*`、`check_panda_right_MOVED_*`：初始 HOME 和各臂独立运动的实际图像。
- 完整回归额外保存 `check_PREGRASP_*`、`check_APPROACH_*`、`check_CLOSE_*`、`check_LIFT_*`、`check_LOWER_*`、`check_HOME_*`，并保留原控制器的 lifted/released/final 输出。`check_HOME_*` 是任务回位帧；早期左臂回归目录尚采用旧命名，初始 HOME 图被回位图更新，独立运动及返回 HOME 图仍分别保留。

`validate_cameras.py` 的回归类只在原控制器阶段切换时附加采集，所有 IK、路径、速度、夹持参数和成功判据继承原类。通过相机输出不能推导出视觉控制、多姿态成功率或全工作空间可见性；每次结果以 `run_status.json` 和物理任务报告为准。

## 最终配置的实测结果与遮挡取舍

`outputs/three_camera_reference_single_regression_01/` 已完成实际运行，退出码 0；Camera sensor validation 与原固定左臂 Single-pick-place physical validation 分别通过。原状态机完整到达 DONE：抬升 `0.1799665 m`、最终 XY 误差 `2.733 mm`、轴向 yaw 误差 `0.0091344°`、稳定保持 `0.5 s`、两臂回 home。控制器未修改，未使用纸盒绑定或直接改位姿。

最终 Scene 的九盒视野改善与抓放阶段的遮挡应分别评价。下放时活动腕部/手掌会遮住 scene 中目标的大部分区域；同一时刻左腕仍能清晰观察纸盒与夹指，撤臂后 scene 能完整看到落位纸盒。当前保留这个已实测的全局/局部观察取舍，没有宣称每阶段 scene 都无遮挡。
