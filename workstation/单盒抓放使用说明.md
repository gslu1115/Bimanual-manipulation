# 单盒抓放使用说明

本功能用于先跑通“确定目标 → 真实夹持 → 抬升搬运 → 松开放置 → 检查结果”。默认左 Panda 操作一个直立纸盒，右臂保持 home。盒子位置读取仿真真值，运动使用 Lula IK 与物理关节驱动；当前没有使用 RGB-D 估计盒子位姿，也没有训练策略。

## 1. 在 GUI 中运行一次完整动作

最方便的入口：在资源管理器中打开 `C:\Users\asus\Desktop\sim\workstation`，双击 `启动单盒抓放.cmd`。它会调用下面同一条启动命令。

关闭不需要的 Isaac Sim 实例，在 Windows PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\asus\Desktop\sim\workstation\launch.ps1" -SinglePickPlace
```

脚本会启动 Isaac Sim、创建场景、让盒子沉降，然后自动抓放。无需先从 GUI 打开 USD，也无需手动按 Play。运行完成后窗口保留，便于查看最终场景；关闭该窗口退出。若发生异常，查看本次目录的 `run_status.json`、`task_report.json` 和 `failure.txt`。

本机已完成一次无窗口实测：总仿真时间约 47.39 秒，包含渲染和保存的实际用时约 5 分 17 秒。机器负载和 GUI 模式会影响用时，运行时可通过 `[pnp]` 阶段日志查看进度。

一次启动执行一次任务。要重新执行，请关闭这次窗口并再次运行同一命令，启动器会创建新的时间戳目录。

只需要计算与保存结果、不看 GUI 时：

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\asus\Desktop\sim\workstation\launch.ps1" -SinglePickPlace -Headless
```

不要同时加 `-ConveyorTest`。不带 `-SinglePickPlace` 的默认模式仍是九盒乱序释放与观测，机械臂不会自动整理那九个盒子。

## 2. 格子在哪里

绿色边框和方向线已经从新场景中移除。落位区仍存在于软件里，但没有几何、碰撞体和相机标签。

打开 `C:\Users\asus\Desktop\sim\workstation\config.json`：

```json
"slots_xy": [[-0.2, -0.40], [0.0, -0.40], [0.2, -0.40]],
"slot_size_xy": [0.15, 0.095]
```

这两个字段都位于 `conveyor` 内，单位为米。三个目标编号依次是 0、1、2；默认单盒放到编号 0，也就是第 1 个落位区。区域尺寸并不等于允许的位置误差，误差阈值在 `verification` 内。

在 GUI 的 Stage 树中展开 `/World/Targets`，选择 `slot_0`、`slot_1` 或 `slot_2`，可查看平移坐标与 `target:sizeXY`。Z 坐标表示盒子中心的目标高度，即传送带顶面加半个盒高；当前为 `0.7825` m。它们是无几何的 Xform，摄像机看不到。

旧输出目录中的 `settled.usda` 保留旧场景内容；需要使用修改后的代码重新运行，才能得到不带格子图形的新文件。

## 3. 单盒参数在哪里

文件仍是 `C:\Users\asus\Desktop\sim\workstation\config.json`，字段为 `single_pick_place`。修改后重新运行才会生效；本次实际参数保存在输出目录的 `config_used.json`。

| 字段 | 当前默认值 | 含义 |
|---|---|---|
| `arm` | `panda_left` | 执行抓放的机器人名称 |
| `box_xy` | `[-0.20, -0.06]` | 初始盒子中心的世界平面坐标，m |
| `box_yaw_deg` | `20.0` | 初始盒子绕竖直轴的角度，° |
| `slot_index` | `0` | 目标编号，只能为 0、1、2；0 对应第 1 个落位区 |
| `lift_height` | `0.18` | 抓取与放置上方运动高度，m |
| `move_speed` | `0.10` | 常规笛卡尔段的设定速度，m/s；靠近、抬升和下放另有较慢速度 |
| `joint_speed` | `0.6` | 关节插值的设定速度，rad/s |
| `grip_position` | `0.018` | 闭合时每根手指的目标位移，m；两指间距约为两倍此值 |
| `grip_max_force` | `30.0` | 每根手指驱动的最大力，N |
| `verify_timeout_s` | `5.0` | 回 home 后等待最终验证的最长仿真时间，s |

被盒子挡住时，实际手指位置通常不会到达 `grip_position`；应查看报告中的实际位置。盒子尺寸与质量在 `boxes.size`、`boxes.mass_kg`，默认分别为 `[0.10, 0.055, 0.045]` m 与 `0.08` kg。

初始盒子的整个旋转投影必须处于托盘内；程序会做基础参数校验。但参数校验不包含完整可达性、避碰或抓取保证。当前抬高路径针对这个工位，改变盒子位置、目标编号、机器人安装位等参数后需要重新做实际验证。

## 4. 怎样判断成功

控制台以 `[pnp]` 输出阶段，报告中也有阶段事件：

| 阶段 | 动作 |
|---|---|
| `PREGRASP` | 手指张开，移动到盒子上方 |
| `APPROACH` | 向盒子靠近 |
| `CLOSE` | 闭合手指形成物理夹持 |
| `LIFT` | 抬升并检查盒子是否实际随夹爪离开台面 |
| `TRANSFER` | 搬运到目标上方，并调整胶带轴朝向 |
| `LOWER` | 向传送带下放 |
| `OPEN` | 松开手指 |
| `RETREAT` | 向上退出 |
| `HOME` | 机械臂回到 home |
| `VERIFY` | 检查盒子实际位置、方向、速度和稳定时间 |
| `DONE` | 成功完成 |

**最终以 `task_report.json` 的 `success` 和 `run_status.json` 的 `status` 判断结果。** 文件夹存在、动作时间结束、盒子曾经经过目标处，均不等于成功。

成功条件包括实际抬升至少 `0.08` m、最终两根手指均张开超过 `0.037` m、两臂回 home，以及盒子在目标处连续稳定满足以下默认阈值：

- 平面中心误差 ≤ `0.018` m，高度误差 ≤ `0.008` m。
- 顶面倾角 ≤ `8°`，胶带轴朝向误差 ≤ `8°`，允许相差 180°。
- 线速度 ≤ `0.015` m/s，角速度 ≤ `0.15` rad/s。
- 连续稳定时间 ≥ `0.5` s。

抓放通过物理接触完成，不使用盒子与手爪绑定，也不改写运行中的盒子坐标。单盒只填满一格，所以任务结束后输送带继续等待另外两格；此时带子不动是当前三格联动规则的正常结果。

## 5. 文件存在哪里、打开哪个

历史上已完成一次固定场景单盒实测，摘要见 `VALIDATION.md`；原始输出目录已清理，`final.usda` 与 `task_report.json` 不再保留。实测抬升约 17.99 cm、最终 XY 误差约 2.74 mm、轴向误差约 0.264°，连续稳定 0.5 s，`task_report.json` 中 `success` 为 `true`。这是当前固定单盒场景的一次通过记录，不是随机场景成功率统计。

每次启动自动新建目录，例如：

```text
C:\Users\asus\Desktop\sim\workstation\outputs\single_pnp_seed_006_20261005_153000\
```

最后一段为实际运行时间，上述目录名仅作格式示例。控制台的 `[ready] Outputs:` 会打印本次目录。推荐使用启动器；直接调用 `run_scene.py` 且不指定 `--output` 时仍写 `outputs/seed_006`，可能覆盖其中同名文件。

| 想查看的内容 | 打开的文件 |
|---|---|
| 最终场景 | `final.usda` |
| 抓取前场景 | `settled.usda` |
| 是否成功、失败原因、抬升与误差 | `task_report.json` |
| 整次程序是否通过 | `run_status.json` |
| 每一阶段的关节目标和实际状态 | `control_trace.jsonl` |
| 抓取前图像 | `settled_overhead_rgb.png`、`settled_oblique_rgb.png` |
| 抬升后图像 | `lifted_overhead_rgb.png`、`lifted_oblique_rgb.png` |
| 松爪后图像 | `released_overhead_rgb.png`、`released_oblique_rgb.png` |
| 最终图像 | `final_overhead_rgb.png`、`final_oblique_rgb.png` |
| 对应深度与实例分割 | 同前缀的 `*_depth_m.npy`、`*_instances.npy/json` |
| 本次参数 | `config_used.json` |

`control_trace.jsonl` 每行是一个 JSON 记录，按约 10 Hz 仿真时间采样，不是视频。失败可能发生在某阶段之前，相应后续图像就不会生成；失败时也可能保存 `final.usda`，必须结合报告判断。如果控制器构造阶段就出错，可能只有 `failure.txt` 和 `run_status.json`，尚未生成 `task_report.json` 或控制轨迹。

在 Isaac Sim GUI 中通过 File → Open 打开 `final.usda`，可以查看最终快照。**单独打开它不能重演抓放，按 Play 也不会加载 Python 控制器。** 要看完整动作，应使用第 1 节的启动命令重新执行。

## 6. 当前功能范围

这一版建立可检查的单盒执行基线：目标是软件坐标，盒子通过物理抓放到目标，然后读取实际状态复核。它尚未实现 RGB-D 感知、从九盒乱序中筛选可抓目标、通用避碰、双臂解锁或强化学习训练。

后续可在这条执行链路上逐步替换真值观测、接入抓取候选与策略。相机数据、真值标签和控制轨迹已分别保存，便于分析，但运行一次演示并不会自动训练出模型。
